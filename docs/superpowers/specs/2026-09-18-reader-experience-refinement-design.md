# AI Reader 整体体验优化设计

日期：2026-09-18

状态：已完成实现、审阅与集成；2026-09-30 PR #22 合并到 main，GitHub CI 通过。最终针对性 E2E 4/4，单测 1378/1378，lint、生产构建及安全门禁通过。完整矩阵与后续性能波动分别保留在实现计划中；本轮未部署生产。

适用产品：面向 iPhone Safari / 主屏幕 PWA 的本地优先 EPUB / TXT 阅读器

## 1. 目标与设计依据

本轮优化集中解决日常使用中的三个问题：操作结果不够明确、意外中断会损失输入、同一本书在不同界面中的信息不一致。保留现有安静、原生、以阅读为中心的界面风格。

设计基于 2026-09-18 对工作树 `feat/pwa-interaction-fluidity`、产品提交 `098079e` 的代码审查和本地 Chromium iPhone 14 尺寸复现。审查时工作树 HEAD 为 `7454172`，`app/`、`lib/`、`public/` 与本地 `origin/main` 一致。这不是对当天远端仓库或生产状态的重新确认。

所有导入、覆盖恢复、AI 请求和更新测试均在独立浏览器上下文中使用模拟数据；AI 和元数据服务经过拦截，不涉及真实图书、密钥或用户书库。浏览器自动化结果不等同于实体 iPhone 验收。

| 编号 | 当前证据 | 体验影响 |
| --- | --- | --- |
| E1 | 两本测试图书存在时，选择有效的空备份后直接恢复为零本，无预览和确认 | 用户可能误以为导入会合并，而实际替换现有数据 |
| E2 | 服务商名称输入未保存时，模拟 BUILD_ID 变化并触发窗口焦点，页面重载后草稿消失 | 发布新版本会中断输入 |
| E3 | 详情显示《资本论》、卡尔·马克思和政治经济学；搜索三个词均无结果，原文件名可命中 | 已显示的信息无法用于找回图书 |
| E4 | 延迟文件读取时无处理中状态；同一测试文件导入两次产生两本书 | 难以判断是否成功，容易重复操作 |
| E5 | 配置模拟服务商后，导入缺少简介的 TXT 自动触发 AI 补全，包含 1250 字符模拟节选 | 当前“提问时发送”的说明未涵盖自动补全 |
| E6 | 深色阅读菜单动画结束后，半透明按钮仍透出可辨认的正文 | 菜单标签与正文互相干扰 |
| E7 | 无效备份显示 `Invalid backup: unsupported version`；详情菜单使用“重新刮削元数据” | 错误不易理解，操作目的不直观 |
| E8 | 详情顶部与下方重复展示少量相同标签 | 占用首屏与滚动空间 |

## 2. 范围和约束

- 保留书库、阅读、设置三个根页面及现有导航结构。
- 阅读界面的显式深色和系统深色继续使用纯 `#000000` 背景；本轮菜单调整也使用不透明纯黑底，不改为灰底或环境透明背景。
- 阅读菜单的样式改动仅作用于阅读界面。书库、设置、Dock、浅色和护眼主题继续沿用现有材料。
- 复用现有 Sheet、焦点恢复、导航、持久化和错误提示机制，不引入新的 UI 框架。
- 保留 EPUB / TXT 位置、笔记、分组和工作区兼容性；备份继续兼容现有 v1、v2、v3。
- 本设计包含文档、交互和局部逻辑优化，不包含云同步、全文检索、批量导入、回收站、备份合并或整体视觉重做。
- 实体 iPhone/PWA 与 APK 端点沿用用户此前的排除决定，不作为本轮实施的阻塞验收项。
- 设计文档不代表已经批准全部产品行为；以下默认值是本草案的明确建议。产品实施、PR 和部署状态分别记录，不以本设计替代发布证据。

## 3. 方案选择

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| A：只做文案和样式 | 中文错误、菜单底色、精简标签 | 改动小，但覆盖恢复和草稿丢失仍然存在 |
| B：分阶段补齐关键流程（推荐） | 先修复数据与输入保护，再改善导入、AI 提示和视觉细节 | 每阶段可独立验收，收益明确，适合当前项目 |
| C：统一重构全部操作流程 | 重建全局任务管理、草稿系统和图书索引 | 范围大，当前证据不足以支持这笔成本 |

采用 B。所有新增机制都有明确使用方，不建立通用工作流引擎。

## 4. 恢复备份：先预览，再替换

### 4.1 用户流程

1. 在设置中选择“从备份恢复”，选择 JSON 文件。
2. 显示“正在检查备份…”，完成大小限制、解析和既有结构验证。此阶段不停止阅读、不取消 AI、不写入数据库。
3. 验证成功后打开“恢复备份”确认页，展示文件名、备份日期、备份中的图书/笔记/对话数量、当前书库数量和受影响的数据范围。
4. 明确提示：“恢复会替换本机现有图书、阅读进度、笔记和对话，不会与当前数据合并。”
5. 提供“取消”“先导出当前备份”和“替换并恢复”。最后一项使用既有危险操作样式。
6. 只有点击“替换并恢复”才执行恢复。成功显示“已恢复 N 本图书”，保留查看书库入口；失败显示可理解的原因及下一步。

若备份图书数量为零，确认页额外显示“该备份不含图书，恢复后当前书库将为空”。取消或返回不会改变任何数据。

“先导出当前备份”只生成并触发下载，之后仍停留在确认页，不自动开始恢复。浏览器无法证明用户已将文件保存到磁盘，提示使用“备份文件已生成，请确认保存后再恢复”，不宣称已完成安全备份。

### 4.2 版本、凭据和状态

- 根据实际备份版本生成影响清单，不暗示旧备份包含全部现代数据。v1 未携带的阅读统计和背景沿用既有保留语义；旧版本缺少的工作区数据会被替换为空，预览必须提示。
- v2/v3 中的服务商配置仍按现有恢复规则替换；导出不含密钥，确认页说明“恢复服务商配置后可能需要重新填写 API Key”。不自动把现有密钥匹配给备份中的服务商。
- 空闲、检查中、待确认、恢复中、成功、失败为独立状态。恢复中禁止二次提交、再次选文件和应用内其他数据写操作；进入实际事务后不提供伪取消。
- 先停止并等待 AI 流、封面补齐、图书信息补全等后台写任务退出，再调用既有位置协调器和恢复保护机制。旧任务不得在恢复后把旧数据写回来。
- 等待后台任务退出最多 10 秒。超时或不能确认写任务已退出时，不启动恢复事务，返回可重试错误并解除界面锁定。允许本地封面任务重新排队，但不自动重发 AI 请求或恢复已停止的生成；已收到的 AI 内容按现有持久化规则保留。
- 复用 `replaceReaderData` 的 IndexedDB 事务；事务失败保持原数据库数据。数据库提交与 localStorage 配置写入不是同一事务，必须分开报告：例如“图书已恢复，服务商设置保存失败，请重新配置”，不得把这种部分成功描述为全部回滚。
- 备份预览使用已验证的同一份载荷，重新选文件时作废旧预览。确认后先取得同源标签页间的写入保护，再在保护范围内停止写任务、校验数据修订并提交；保护覆盖进度、后台补全与手动编辑等写入。若其他标签页已修改数据，解除保护并重新预览，不能依赖过期数量确认，也不能在修订检查和提交之间放入新的写操作。尚未采用该协调机制的旧版本标签页需要关闭后再恢复，不宣称能约束旧页面的写入。
- 浏览器外部强制关闭不承诺可取消；依靠数据库事务和既有生命周期保存保证可恢复边界。

## 5. 版本更新：保护正在进行的工作

### 5.1 可见行为

- BUILD_ID 检测和 Service Worker 更新只产生“有可用更新”的状态，不因检测、回到前台或控制器变化而直接重载页面。
- 非阅读页面可显示一条轻量提示：“新版本可用”，操作为“立即更新”“稍后”。同一版本选择稍后后，本次会话不反复弹出；设置中保留更新入口。
- 沉浸阅读、键盘输入和 AI 输出期间不弹遮挡式提示；退出阅读后或进入设置时可查看待更新状态。
- 点击“立即更新”时检查未保存表单、未发送问题、笔记编辑、正在导入/恢复和 AI 输出。
- 有草稿：提示“更新会清除尚未保存的输入”，提供“继续编辑”“放弃输入并更新”；不把含密钥的表单自动存入额外存储。
- 正在导入或恢复：提示“操作完成后可更新”，不插入中途重载。AI 输出中提供“继续等待”或“停止生成并更新”，停止后先保存已经收到的内容。
- 无阻塞操作或用户明确选择放弃输入后，等待进度和已提交工作区内容保存成功，再激活更新并重载一次。保存失败时保留当前页面并提示重试。

### 5.2 技术约束

- 统一收敛 BUILD_ID、`controllerchange` 和主动更新入口，避免两个入口分别重载。
- 保留周期检测和离线容错；离线、检测失败、首次访问都不伪报新版本。
- 区分“正在运行的版本”和“已发现的版本”。选择稍后不能把运行版本标记成新版本，刷新或恢复页面后仍能正确判断更新状态。
- 审核 `public/sw.js` 中的 `skipWaiting()`、`clients.claim()` 和缓存清理。新 Worker 已激活也不能触发客户端强制重载；迁移后优先让新 Worker 等待用户更新指令，首次安装仍可正常生效。
- 延后更新期间保留当前页面所需旧资源；清理仍限制在 `ai-reader-*` 命名空间。多标签页中，一处更新不得强迫另一处丢弃草稿；旧缓存只有在没有旧客户端使用或下一次可确认安全的生命周期中才回收。
- 首次发布此机制时，旧页面仍运行旧的自动刷新逻辑，无法由新代码追溯保护。上线说明必须区分这一次迁移与后续版本更新；不声称第一次部署已保护所有旧客户端草稿。

## 6. 搜索：显示的信息都能用于找书

搜索字段扩展为本地书名、原文件名、补全书名、作者、标签和文件格式。简介和正文暂不进入搜索。

- 原始字段不改写；搜索时统一 Unicode NFKC、首尾空白、连续空白与大小写。
- 多个空格分隔词采用 AND 匹配，每个词可以命中不同字段。例如“马克思 资本论”可以同时命中作者和补全书名。
- 保持当前结果顺序和渐进渲染，不引入远端搜索、拼音依赖或新的排序选项。
- 用户自定义书名优先保留。若补全书名不同，结果中补充该书名；作者/标签命中时显示简短的对应信息，避免用户不知道为什么命中。
- 空查询展示全部图书；无结果保留现有清除搜索入口。
- 搜索进入详情再返回时，继续保留查询、滚动位置、视图模式和焦点。

自动元数据更新只增补检索字段，不覆盖用户重命名。查询永远在本机处理。

## 7. 导入：可感知、可恢复、避免重复

### 7.1 状态和反馈

采用单文件流程：选择文件 → 读取/检查 → 重复判断 → 保存 → 成功或失败。开始处理后立即显示文件名和“正在导入…”，禁用重复触发入口；超过短暂等待后可显示具体阶段，不展示无法准确测量的百分比。

成功时用非阻塞状态提示“已导入《书名》”，提供“查看图书”，不自动把用户带离当前页面。图书信息补全属于后续后台任务，不延长“导入中”。失败保留重选入口，明确是格式不支持、文件损坏、空间不足还是存储不可用。

读取/重复检查阶段允许取消，取消后以任务标识丢弃晚到结果；进入数据库保存阶段短暂禁用取消。界面不得承诺底层文件读取一定能物理中断。

### 7.2 重复文件

- 精确重复定义为同格式、同字节内容；相同文件名不是充分条件。
- 先用已有文件大小和格式筛选候选，仅对候选进行本地摘要比较；摘要只用于重复判断，不上传。
- 首版不升级数据库或批量给全部书籍计算哈希，摘要按需计算并在本次会话缓存，分配内存时复用已有输入缓冲区，候选文件顺序处理。
- 命中时展示已有书名和阅读进度，提供“打开已有图书”“仍然导入一本”“取消”。“打开”进入已有详情，保持之前的位置和笔记。
- 同内容改了文件名仍识别为重复；同名但内容不同正常导入。
- 当前页只允许一个导入任务；多标签页的并发保存需使用已有或轻量的互斥/提交前复查机制，并纳入验证。检测失败时不能直接宣称“不重复”，应允许用户取消或明确继续导入。
- 不自动覆盖现有图书，也不自动合并两本书的进度。

## 8. AI 补全：用途和发送范围明确

### 8.1 设置与默认行为

在现有 AI 设置中增加“自动用 AI 补全图书信息”开关，说明“缺少简介或标签时，会向当前服务商发送书名、已知信息及必要的开头节选”。

- 本草案建议新用户及没有显式偏好记录的老用户默认关闭；已有服务商配置不视为已同意自动发送正文。
- 开启开关只影响之后的新图书导入和用户主动发起的“更新图书信息”，不扫描已有书库、不自动补发已取消或失败的任务。旧书需要用户逐本触发，重新开启也不产生批量请求。
- 开关是设备本地偏好，刷新后保留；旧备份恢复不打开该开关，也不回填不存在的同意记录。
- 关闭仅禁止后台自动 AI 补全，不影响主动提问、已有简介或公共书目查询。开关关闭时取消尚未发送的任务；已经发出的请求无法撤回，阻止其后续自动请求。
- 公共书目补全继续默认运行，只发送书名、作者、标识符等查询信息，不发送正文。图书信息相关说明要明确公共书目查询与 AI 补全的区别。
- 手动“更新图书信息”先查公共来源；仍有缺项且开关关闭时，提供“用 AI 补全这本书”的单次明确操作，显示服务商与发送范围，不隐式修改全局开关。
- 开关开启时只在确有缺项且服务商可用时发送 AI 请求；沿用现有节选上限和服务端限制，不发送整本书。自动任务因提供商错误失败后不自行循环重试。
- 开关仅控制图书信息补全；明确的手动请求在发送前再次校验授权路径。关闭后不能通过已经排队的自动任务绕过限制。

### 8.2 文案与可识别性

- 密钥说明改为：“API Key 保存在本机浏览器；调用服务时会通过应用接口用于向所选服务商认证。备份不包含密钥。”
- 保留请求字段和长度限制。界面不把完整密钥、正文节选或原始服务商错误写入日志或状态提示。
- AI 生成简介在简介附近标注“AI 生成”，公共书目来源继续显示来源名；混合来源不能仅用“已补全”模糊表达。
- 未配置服务商、离线或额度不足时，导入与阅读仍正常；失败不清除已取得的公共信息。
- 实施时同步校正 `PRODUCT.md` 中“AI requests use only selected text”的过时描述，使其与主动提问上下文和自动补全规则一致。

## 9. 阅读菜单与信息细节

### 9.1 深色阅读菜单

- 显式 Dark 与系统 Dark 的阅读菜单、关闭按钮和页码浮层采用不透明 `#000000` 底色；用细边框和现有文字颜色区分边界。
- 同步调整按压态，避免按下后又变透明、正文重新透出。正文背景、EPUB 媒体和页面布局不变。
- 不增加大面积模糊效果；沿用现有进出场与减少动态效果逻辑。
- 字体、图标、位置和点击区域保持当前布局；重点验证长正文背后的菜单文字清晰可读。
- “主题与设置”尾部的“大小”改为能正确表达进入设置的既有图标，避免误解为只能调整字号。

### 9.2 图书详情和重试

- “补全元数据”统一为“补全图书信息”，“重新刮削元数据”统一为“更新图书信息”。
- 失败状态旁直接提供“重试”，不要求再打开更多菜单；失败重试遵循前述 AI 开关和单次授权规则。
- 无匹配显示“未找到匹配的图书信息，仍可正常阅读”；离线、超时和服务异常使用对应提示，不把所有失败称为离线。
- 少于等于三个标签时只保留顶部标签；超过三个时顶部展示前三个及“查看全部标签”，点击滚动到包含全部标签的下方区域。无剩余标签时不生成重复区块。
- 长简介默认最多展示六行，超出时提供“展开简介”，展开后可收起；不重置整个详情页滚动位置。按钮状态通过 `aria-expanded` 表达。

### 9.3 错误与状态文案

| 场景 | 用户可见文案方向 | 下一步 |
| --- | --- | --- |
| 备份结构不合法 | “这不是有效的 AI Reader 备份文件。” | 重新选择 |
| 备份版本不支持 | “当前版本无法恢复这个备份，请先更新应用。” | 查看更新/重新选择 |
| JSON 无法解析 | “备份文件无法读取，可能已损坏。” | 重新选择 |
| 超过既有 500MB 限制 | 保留现有容量限制说明 | 选择较小备份 |
| 可识别的存储空间不足 | “本机存储空间不足，未完成导入。” | 保留书库并重试 |
| 无法分类的恢复错误 | “恢复未完成，请重试。” | 重试，保留明确的数据状态 |

只有确认原数据未变时才能显示“原数据未改变”；部分成功按实际阶段解释。状态文字通过既有 `role="status"` 或 `role="alert"` 宣告，不依赖颜色或短暂 toast 承载关键结果。

## 10. 代码边界与兼容策略

| 范围 | 现有落点 | 设计约束 |
| --- | --- | --- |
| 恢复预览与提交 | `app/SettingsSurface.tsx`、`app/page.tsx`、`lib/backup.ts`、`lib/backupRestoreGuard.ts`、`lib/db.ts` | 验证与提交分开；预览无副作用；沿用事务和位置保护 |

| 导入 | `lib/importBook.ts`、`app/page.tsx`、现有文件与数据库方法 | 导入协调状态局部抽取；避免扩大 Home 编排文件 |

## 11. 实施阶段与验收

本文件是总设计，各阶段拆分为独立实施计划和提交，阶段间不要求一次上线。

### 阶段一：保护数据、保护输入、修复搜索

| 编号 | 验收场景 | 通过标准 |
| --- | --- | --- |
| A1 | 选择有效备份后取消 | 所有原数据、阅读状态、后台任务保持不变 |
| A2 | 恢复零本备份 | 明示空书库影响，确认前不修改数据 |
| A3 | 写任务退出超时、跨标签页修订变化、数据库写入失败 | 超时不开始事务，修订变化要求重新预览，事务失败保留原数据，无旧任务迟到写入 |
| A4 | v1/v2/v3、无效文件、配置写入失败 | 预览符合版本语义，错误中文可恢复，部分成功不误报 |
| A5 | 有草稿时发生 BUILD_ID 或控制器变化 | 不自动重载；主动更新可以返回继续编辑 |
| A6 | 导入、恢复或 AI 输出中主动更新 | 按规则等待/停止、保存；最多重载一次 |
| A7 | 两个标签页及离线状态 | 不强制丢弃另一标签页草稿，当前离线阅读资源可用 |
| A8 | 原书名、文件名、补全书名、作者、标签及混合关键词 | 均按定义命中，回退空查询与无结果行为正确 |
| A9 | 搜索 → 详情 → 阅读 → 返回 | 保持原查询、滚动、焦点和图书进度 |

### 阶段二：导入反馈与 AI 使用控制

| 编号 | 验收场景 | 通过标准 |
| --- | --- | --- |
| B1 | 人为延迟读取并再次点击导入 | 有明确状态，不重复启动；取消后的迟到结果不保存 |
| B2 | 同内容同名/改名、同名不同内容 | 精确区分；默认不覆盖旧图书及其进度 |
| B3 | 两标签页接近同时导入同文件 | 复查/互斥生效；不会静默重复创建 |
| B4 | 老用户已有服务商但没有新偏好 | 公共查询可用，自动 AI 请求数为零 |
| B5 | 打开/关闭/重新开启 AI 自动补全、单次手动补全 | 仅符合对应授权路径时发送，不追溯批量处理旧书，排队自动任务服从关闭操作 |
| B6 | 离线、服务商错误、无匹配 | 导入和阅读可用，公共信息保留，不循环请求 |

### 阶段三：阅读材料、详情与文案

| 编号 | 验收场景 | 通过标准 |
| --- | --- | --- |
| C1 | Dark / System Dark 长正文、菜单展开与按压 | 阅读底色及浮层底色纯黑，正文不透过按钮；标签可读 |
| C2 | Light / Sepia、非阅读页面 | 既有背景与材料不受阅读菜单规则影响 |
| C3 | 0/1/3/多标签与短/长简介 | 标签呈现符合数量规则，展开/收起可用，无空区块 |
| C4 | 补全失败、备份失败 | 文案易懂，重试可达，关键结果有无障碍宣告 |
| C5 | 200% 文本、键盘、减少动态效果 | 无截断关键信息，焦点可见且返回正确，不依赖动画完成操作 |

每阶段先运行与改动风险对应的单元测试和针对性浏览器场景；实施提交前遵守仓库现有 Vitest、lint、生产构建、native-navigation 和差异检查要求。测试仅使用隔离存储及模拟服务商。视觉微调以稳定状态截图、实际点击和对比度检查为主，不增加只匹配 CSS 字符串的测试。

不因为本设计修改性能门槛或用重试覆盖首轮失败；实体设备与 APK 继续作为非阻塞范围外事项。

## 12. 设计结论

建议按阶段一、阶段二、阶段三的顺序实施。成功标准是：恢复前知道会替换什么，更新不会突然丢输入，看到的图书信息能够搜到，导入能看见结果，AI 自动行为可控制，纯黑阅读界面的操作文字清楚。

本次交付仅为设计文档。下一步实施计划应逐项映射 A1–C5，并记录实际产品改动及验证证据。
