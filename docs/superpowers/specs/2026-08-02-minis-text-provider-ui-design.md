# Minis 风格文字 AI 服务商 UI 设计规格

**日期：** 2026-08-02  
**状态：** 已批准，进入实现  
**范围：** PWA 文字 AI 服务商管理、配置、模型发现与模型维护

## 目标

把现有 AI 服务商设置改造成接近 Minis 的 iOS grouped-form 体验：用户可以快速浏览已配置服务商、添加文字服务商、编辑连接信息、刷新模型并在刷新失败时继续使用已有模型或手动添加模型。浅色、深色和系统主题都必须保持同一套层级与可读性。

实现复刻 Minis 的信息架构、视觉层级、状态反馈和交互节奏，不复制其 Swift/GPL 源码、图片、图标或实现细节。本项目继续使用独立的 TypeScript/React 代码与现有 MIT 许可。

## 用户流程

### 1. 服务商列表

- 顶部导航保留返回、编辑和添加入口。
- 列表按文字服务商/协议分组；每一行显示配置状态圆点、用户标签、认证方式与掩码后的 Key、模型数量和进入详情的箭头。
- 已配置但模型为空、刷新失败或缺少必要字段时，状态圆点和辅助文案要表达“需要处理”，不能只显示绿色成功状态。
- 编辑模式支持删除或批量处理，但删除必须有确认步骤；普通点击进入配置详情。
- 添加入口使用轻量 popover/menu，提供“添加 AI 服务商”和“导入服务商配置”。

### 2. 添加服务商

- 添加页采用单列、分组卡片和稳定的顶部取消按钮。
- 只展示文字服务商协议：
  - OpenAI / 兼容 API
  - Anthropic / 兼容 API
  - Google Gemini
  - OpenRouter
  - 自定义兼容接口
- 每项显示名称、协议说明、典型服务商和箭头；点击后生成带默认地址/协议的配置草稿。
- 页面底部保留说明文字，明确允许同一服务商创建多个实例。
- “导入服务商配置”支持本项目的 JSON 备份格式，不读取或显示其他设备的明文 Key 以外的数据。

### 3. 配置详情

- 顶部显示返回、配置标题和关闭/完成动作；在窄屏和键盘出现时不能产生横向滚动。
- 连接分组包含：
  - 标签/名称
  - API Key，默认掩码，支持显隐切换；输入框不可自动大写、不可自动纠正
  - 自定义 API 地址（可选）
  - 自动附加 `/v1` 开关；若地址已包含默认路径，不重复附加
  - API 格式选择：OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Gemini
- 必填字段不完整时，保存按钮保持禁用并提供就近提示；提交时再次校验，不能依赖按钮状态。
- 保存成功后返回服务商列表，并把当前服务商设为可用/激活候选；保存失败不丢失草稿。

### 4. 模型管理

- 配置详情或服务商详情中提供独立的“模型”分组。
- 分组头部显示刷新胶囊按钮；刷新期间显示小型进度指示，按钮不可重复点击。
- 模型行显示模型 ID、来源（远程/手动）和选中状态；重复 ID 合并，手动条目优先保留。
- 刷新成功显示新增数量和时间；刷新失败保留原有模型，提供可读的错误分类和重试入口，并允许继续手动添加模型。
- 手动添加最少需要模型 ID；名称可选，空白和重复 ID 要在本地拦截。
- 删除模型需保持当前默认模型有效；删除默认模型时自动选择剩余第一项，若没有模型则清空默认值并提示。

## 视觉与交互系统

- 使用现有 PWA 主题变量，新增 grouped-form 所需的表面、分隔线、次级文字、状态色和焦点色，不在组件中写死“深色模式颜色”。
- 浅色模式使用低对比度灰色表面与蓝色主动作；深色模式使用分层深灰表面、足够的正文/辅助文字对比度和同一蓝色语义。
- 圆角、分组内边距、行高和箭头位置以截图中的 iPhone 密度为基准，同时支持动态字体/200% 文本而不裁切。
- 页面推入、返回、popover、刷新状态和保存反馈沿用现有 motion roles；禁止对大面积 surface 使用动画 `filter`，优先 transform/opacity。
- 交互状态必须完整：默认、按下、聚焦、禁用、加载、空模型、成功、错误、删除确认、键盘可见和 reduced motion。
- 所有图标提供可访问名称；装饰图标隐藏；状态不能只靠颜色表达。

## 数据与请求边界

- 复用现有 `AiProviderConfig`、本地设置持久化和模型去重逻辑，不引入第二套 provider schema。
- 保留 `/api/models` 作为模型发现的服务端边界，API Key 不写入 URL、不写入日志；客户端只保留必要的本地状态。
- `/api/models` 必须把上游状态安全映射为可诊断但不泄漏凭据的错误类别：认证、余额/限流、网络/超时、非法地址、响应格式和未知错误。
- 上游失败时不得清空现有远程/手动模型；只有明确成功且返回合法列表时才替换远程模型。
- 现有 OpenAI-compatible、Anthropic-compatible、Gemini 请求构建与解析能力继续保留；本次不增加语音、音频模型或原生 OAuth。

## 组件边界

- `AiSettingsSurface` 负责设置入口和 provider 列表/详情状态机，不承担上游协议解析。
- 新增/拆分的 provider UI 子组件只负责展示和用户事件；所有草稿更新通过显式回调或受控 state 完成。
- `lib/aiProviders.ts` 负责默认地址、路径归一化、协议能力与安全字段；`lib/aiModelList.ts` 负责请求构建与模型响应解析。
- `app/api/models/route.ts` 负责请求校验、上游调用和安全错误映射；不在 React 组件里重复实现 fetch 或错误分类。

## 验证策略

- Vitest：provider 草稿校验、地址归一化、模型去重/默认模型回退、错误分类、导入导出兼容。
- React/集成测试：列表分组、添加菜单、协议卡片、配置字段、显隐 Key、刷新 loading/success/error、手动模型操作和删除确认。
- Playwright：iPhone 15 Pro Max 视口下验证浅色/深色/系统主题、真实点击链路、popover 关闭、键盘避让、页面返回、reduced motion、200% 字体无横向溢出。
- 验收门槛：`npm.cmd test -- --run`、`npm.cmd run lint`、`npm.cmd run build`、`git diff --check` 均通过；新增交互测试不得依赖真实 API Key。

## 非目标

- 语音服务商、TTS/ASR 模型和语音对话。
- iOS Keychain、iCloud 强制同步、原生 OAuth 登录和系统级凭据管理。
- 复制 OpenMinis 的源码、图片、SF Symbols 使用方式或 GPL 代码结构。
- 云端 provider 账号、跨设备同步和远程模型目录缓存。

## 成功标准

用户在 PWA 中完成“打开服务商列表 → 添加文字服务商 → 配置 API → 保存 → 刷新模型 → 刷新失败后查看原因/手动添加 → 返回列表”的全流程时，界面层级、反馈时机和操作密度接近截图中的 Minis，且在浅色和深色模式下均可读、可操作、可恢复。
