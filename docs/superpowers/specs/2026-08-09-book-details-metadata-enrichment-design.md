# AI Reader 图书详情与元数据补全设计

**日期：** 2026-08-09

**状态：** 已确认，待实施

**范围：** 图书详情 Push 页面、公开元数据刮削、现有 AI 服务补缺、导航与转场适配

**不包含：** 收藏、分享、远程书店、书评、推荐、元数据候选选择器

## 目标

将“点击图书立即进入阅读器”改为“书库或搜索 → 图书详情 → 阅读器”。详情页在不读取完整书籍文件的前提下，立即展示本地已有信息、阅读状态和阅读入口，再以不阻塞的后台任务补齐作者、简介、标签、出版社、出版日期、语言、ISBN 和缺失封面。

功能必须像现有产品自然延伸：复用当前环境背景、卡片、蓝色强调色、悬浮 Dock、Push 导航、共享书籍转场、动效 token 和无障碍规则，不复制参考软件的米黄色背景、金色主题、素材或品牌表达。

## 已确认决策

- 多个公开候选自动采用相似度最高的可靠结果，不增加人工候选选择页。
- 公开数据库优先；公开来源缺少简介或标签时，才使用当前激活的 AI 服务商补齐。
- 导入成功后自动、非阻塞地尝试一次；详情页更多菜单提供手动补全或重新刮削。
- AI 补缺可以发送截断后的书籍开篇片段，但仅在确实需要 AI 时发送。
- 详情是历史安全的 Push 页面：左上角返回，底部 Dock 保持可用；返回恢复来源页面的滚动位置和焦点。
- 切换根标签会离开详情页。
- 本期不做收藏和分享。
- 刮削永不修改阅读进度、目录、分组、书签、高亮、批注或阅读工作区。
- 刮削失败不影响导入、打开详情或进入阅读器。

## 现有约束

当前 `BookMetadata` 只保存书籍 ID、显示标题、格式、文件名、大小、创建/最近打开时间、分组和封面。书库启动只加载元数据与独立封面，完整 `fileBlob` 仅在阅读、导出或备份单本书时读取。

新功能必须维持这个成本边界：打开详情页不得调用 `getBook()`，也不得为了显示详情扫描所有书籍文件。只有用户点击“开始/继续阅读”、EPUB 的“查看目录”，或者 AI 补缺确实需要开篇文本时，才读取当前单本书的文件。

## 页面与导航架构

### Push 路由

在 `PushRoute` 增加 `book-details`，条目携带：

- `bookId`：详情对应的本地图书；
- `restoreFocusId`：来源书籍按钮的稳定 ID；
- 来源 Push 栈由现有 `NavigationStack` 自然保留，不额外保存“来自书库还是搜索”。

书库列表、书库网格、精选书籍和搜索结果的主点击统一调用 `openBookDetails(book, originId)`。图书更多操作按钮继续打开现有书籍操作 Sheet，不经详情页。

`AppPushSurfaces` 根据 `book-details` 渲染 `BookDetailsSurface`。详情只接收 `BookMetadata`、该书阅读位置和回调，不拥有全局导航或阅读器状态。

### 返回与根导航

- 从书库进入详情，返回恢复书库原筛选、显示模式、滚动位置和被点击书籍的焦点。
- 从搜索进入详情，返回恢复搜索查询、结果滚动位置、列表/网格模式和焦点。
- 浏览器返回、应用返回按钮和边缘返回手势统一 `pop` 同一个 Push 条目。
- 详情期间显示默认根 Dock，而不是搜索输入 Dock；返回搜索后，搜索 Dock 恢复。
- 点击书库、阅读或设置根标签使用现有根导航语义并清除 Push 页面。
- 详情中的图书若被其他流程删除，安全弹回最近仍有效的页面，不保留失效详情。

### 进入阅读器

详情主操作根据阅读位置显示“开始阅读”或“继续阅读”。点击后才执行现有完整打开链路：

1. `getBook(bookId)` 读取当前单本书文件；
2. 更新 `lastOpenedAt`；
3. 读取保存位置；
4. `prepareReaderBook()`；
5. 呈现阅读器。

EPUB 可显示次操作“查看目录”。它复用同一加载链路，在阅读器准备完成后打开现有目录 Sheet，不另建第二套 EPUB 目录解析与持久化。TXT 没有可靠目录时不显示该次操作，主按钮占满可用宽度。

## 详情页信息架构

从上到下为：

1. 顶部返回按钮和更多按钮；
2. 封面、当前本地显示标题、公开作者、标签、短简介与来源状态；
3. 开始/继续阅读主按钮，以及适用时的 EPUB 查看目录次按钮；
4. 阅读状态、阅读进度、最近阅读时间和文件格式/大小；
5. 完整简介与标签；
6. 出版社、出版日期、语言、ISBN 和原文件名等书目信息。

展示规则：

- 本地 `title` 始终是主标题。刮削得到的标准书名只作为书目信息，不覆盖用户重命名结果。
- EPUB 内嵌封面优先于远程封面；只有没有本地封面，或当前封面明确来自上次刮削时，手动重刮才可更新远程封面。
- 缺失字段不显示空标签或“undefined”，整个行或区块自然省略。
- 长标题和作者最多显示合理行数并允许详情正文完整展示，不横向溢出。
- 元数据更新时间与来源使用低强调度文本，例如“已补全 · Open Library · 刚刚”。
- 未执行过的旧书在菜单显示“补全元数据”；已有刮削记录时显示“重新刮削元数据”。

## 视觉系统

- 页面背景继续由现有 `AmbientBookBackground` 提供。当前书有封面时以该书为环境背景来源；无封面时回退现有 `--app-bg`。
- 卡片、分隔线、文字、主按钮和控制填充分别复用 `--surface-primary`、`--hairline`、`--text-*`、`--tint` 和 `--control-fill`。
- 详情卡片使用当前 13px 左右的克制圆角与 0.5px 分隔线，不增加重阴影、装饰渐变或新的玻璃层。
- 顶部圆形按钮与底部 Dock 复用现有材质、边框、阴影和 44px 最小触控目标。
- 浅色、深色、系统主题、护眼主题和自定义背景均只通过现有 token 响应，不硬编码参考图配色。
- 390×844 为首要移动验收尺寸；更窄屏幕允许信息区纵向重排，不缩小触控目标。

## 动效与交互

### 书库到详情

- 图书按压继续使用当前书籍项反馈。
- 列表或网格封面通过现有共享书籍转场移动到详情顶部信息区。
- 详情正文交叉淡入并上移不超过 8px；底部 Dock 保持挂载和几何稳定。
- 入场使用现有约 280ms 导航时长与 `--ease-navigation`，无弹簧或回弹。
- 返回使用约 200ms 退出时长，反向还原共享封面并恢复焦点。

### 详情到阅读器

继续复用现有阅读器转场和内容就绪门槛，不再叠加一套新的全屏动画。快速重复点击主按钮时只允许一次加载和一次导航提交。

### 元数据局部更新

- 详情先立即渲染本地信息，不等待网络，也不使用整页骨架屏。
- “正在补全”只在来源状态行使用轻量进度符号；预留稳定区域，避免信息到达时推动主要操作。
- 成功字段在原位置做短交叉淡入，不对整个页面重放入场动画。
- 自动任务不弹 Toast、不抢焦点。
- 手动失败在页面内显示“暂时无法补全，可稍后重试”，阅读按钮始终可用。
- 同一本书同一时刻只有一个刮削任务；更多菜单项在执行期间显示“正在重新刮削”并禁用。

### 更多菜单

右上角更多按钮复用现有 popover 语义和 motion 角色。菜单本期只有元数据操作及必要状态，不加入收藏或分享。点击外部、再次点击按钮或按 Escape 关闭，焦点返回更多按钮。

### Reduced Motion

系统或应用开启减少动态效果后：

- 取消共享封面的几何移动；
- 使用不超过 100ms 的交叉淡入；
- 取消按压缩放与位移；
- 保持焦点、导航和内容更新顺序不变。

## 元数据来源

### Open Library

Open Library Search API 作为无需应用密钥的基础公开来源，Cover API 用于缺失封面的候选。实现遵守其官方建议，以搜索接口获取结果，避免为大量候选逐本请求详情。[Open Library Developer Center](https://openlibrary.org/developers/api)

### Google Books

Google Books 可补充标题、作者、出版社、出版日期、简介、分类、封面和行业标识。生产请求按官方要求使用服务端环境变量 `GOOGLE_BOOKS_API_KEY` 进行应用识别；未配置时静默跳过 Google Books，Open Library 仍然可用。密钥不发送到浏览器、不写入 IndexedDB、不进入备份。[Google Books API: Using the API](https://developers.google.com/books/docs/v1/using)

### 来源优先级

服务端同时归一化所有可用来源，不用固定来源顺序覆盖匹配质量。选择逻辑先看候选分数，再以字段完整度和稳定来源 ID 作为确定性平局规则。Google Books 不可用、限流或超时时，Open Library 的有效结果仍可独立成功。

## 数据模型

`BookMetadata` 增加一个可选、可向前兼容的补全对象，而不是把远程字段散落到现有顶层：

```ts
type BookMetadataSource = "open-library" | "google-books" | "ai";

type BookMetadataField =
  | "bibliographicTitle"
  | "authors"
  | "description"
  | "subjects"
  | "publisher"
  | "publishedDate"
  | "language"
  | "identifiers"
  | "cover";

type BookMetadataProvenance = {
  source: BookMetadataSource;
  sourceId?: string;
  generated?: boolean;
};

type BookEnrichment = {
  bibliographicTitle?: string;
  authors?: string[];
  description?: string;
  subjects?: string[];
  publisher?: string;
  publishedDate?: string;
  language?: string;
  identifiers?: Array<{ type: string; value: string }>;
  status: "pending" | "complete" | "partial" | "failed";
  matchScore?: number;
  attemptedAt: string;
  updatedAt?: string;
  errorCode?: "no-match" | "offline" | "timeout" | "provider" | "invalid-response";
  fieldSources?: Partial<Record<BookMetadataField, BookMetadataProvenance>>;
};
```

`BookMetadata` 新增 `enrichment?: BookEnrichment`。实际封面 Blob 继续存放在 `bookCovers`，`fieldSources.cover` 记录当前封面是否来自刮削；没有该来源记录的既有封面一律视为本地优先封面。

不为新字段建立 Dexie 索引，因此无需破坏性迁移或全库扫描。旧记录缺少 `enrichment` 时按“尚未补全”处理。

## 导入与触发

### 本地查询信息提取

EPUB 导入时在现有 ZIP/OPF 读取路径中提取 `dc:title`、`dc:creator`、`dc:identifier` 和 `dc:language`，并与封面提取共用解析结果，避免重复解压。TXT 继续从文件名推导标题，不猜测作者或 ISBN。

本地显示标题仍由现有导入与重命名规则控制；OPF 标题只作为检索提示和标准书名候选。

### 自动任务语义

“后台自动刮削”指图书已事务性保存、书库已可用后，在当前前台会话中启动非阻塞任务；不引入 Service Worker Background Sync、服务器作业队列或操作系统后台执行承诺。

流程：

1. `saveBook(record)` 成功；
2. 书库立即刷新并允许打开详情/阅读；
3. 将该书 `enrichment.status` 写为 `pending`；
4. 启动当前单本书的补全协调器；
5. 成功或失败后只更新该书元数据与必要封面，再增量刷新书库状态。

应用退出可能中断前台请求。超过五分钟仍为 `pending` 的记录在下次读取时按可重试失败态展示，避免永久旋转；不自动批量重试旧书。旧书可在详情页手动补全。

## 服务端接口

公开查询与 AI 补缺分为两步，确保公开来源足够时完全不发送正文片段或用户 AI 密钥。

### `POST /api/book-metadata/search`

请求只包含有长度限制的查询字段：

```ts
{
  title: string;
  authors?: string[];
  identifiers?: Array<{ type: string; value: string }>;
  language?: string;
  format: "epub" | "txt";
  needsCover: boolean;
}
```

响应返回一个已接受的归一化候选，或明确的 `no-match`：

```ts
{
  candidate: NormalizedBookCandidate | null;
  matchScore?: number;
  missing: Array<"description" | "subjects">;
}
```

服务端固定访问 Open Library 和配置后的 Google Books 域名，单提供方使用短超时、有限重试和响应大小上限。部分提供方失败不取消其他有效结果。

若需要缺失封面，客户端使用服务端生成的来源类型与稳定来源 ID 调用受限封面端点。封面端点不接受任意 URL，只能构造已知提供方地址；限制图片 MIME、重定向次数和最大 2 MB 响应，校验后才写入 `bookCovers`。

### `POST /api/book-metadata/complete`

仅当公开结果缺少简介或标签、当前存在可用 AI 服务商时调用：

```ts
{
  provider: AiProviderConfig;
  knownMetadata: BoundedKnownMetadata;
  missing: Array<"description" | "subjects">;
  excerpt?: string;
}
```

实现复用现有 `sanitizeAiProvider`、`hasUsableAiProvider`、`readLimitedJson`、`fetchAiUpstream` 和 SSRF 防护。开篇片段清除多余空白并截断到最多 6,000 个字符；请求总长度和返回长度均受限。

AI 必须返回严格结构化 JSON。服务端只接收请求中列出的缺失字段，丢弃额外键、HTML、过长内容和无效类型。AI 结果标记 `generated: true`，不能成为 ISBN、作者、出版社、日期、语言或标准书名来源。

API 密钥沿用当前聊天功能的请求模式：只从浏览器发送到本应用服务端，再发送给用户选择的 AI 服务商；不记录、不持久化、不进入错误正文或备份。

## 候选匹配

所有字符串先做 Unicode 归一化、大小写折叠、标点/多余空白清理和常见副标题分隔处理。ISBN 去除连字符并校验长度。

候选分数为 0–1，依据：

- 有效 ISBN 精确一致具有最高决定权；
- 标准化标题相似度是无 ISBN 时的主要权重；
- 作者集合重合用于排除同名书；
- 语言和出版年份只作小权重辅助；
- 格式不参与书目匹配；
- 信息完整度只用于同分候选的平局处理，不可把错误候选推过安全阈值。

默认最低接受阈值为 0.72。标题明显冲突时，即使其他字段偶合也拒绝。多个通过阈值的候选自动采用最高分；完全同分时依次选择 ISBN 更完整、作者更一致、描述更完整、稳定来源 ID 字典序更小的候选，保证测试与重复刮削结果确定。

阈值和权重集中在纯函数模块中，先用真实中英文书名、卷册、副标题和译者噪声夹具测试，再允许调整；不把魔法数散落在路由或组件中。

## 合并与覆盖规则

补全结果通过单一纯函数合并：

- 永不覆盖顶层本地 `title`、`fileName`、`format`、`size`、`createdAt`、`lastOpenedAt` 或 `groupIds`。
- 自动补全只填空字段。
- 手动重新刮削可更新上次由公开来源或 AI 生成的字段，但不能覆盖没有刮削来源标记的本地字段。
- 公开简介优先于 AI 简介；公开分类优先保留，AI 标签仅补充去重后的缺口。
- 数组去空、去重并设置合理数量上限；描述保存纯文本与长度上限。
- 本地/内嵌封面永不覆盖；远程封面仅在缺失封面或现有封面明确为远程刮削结果时更新。
- 合并元数据、来源、状态和封面来源必须保持一致；任一步校验失败都不留下“成功状态 + 未保存内容”。

阅读位置、统计、注释、分组和工作区位于独立表或独立字段，补全更新函数不得接收这些值，也不得调用它们的写接口。

## 状态与错误处理

状态机：

```text
未补全 → pending → complete
               ↘ partial
               ↘ failed
failed / partial / complete → 手动重刮 → pending
```

- `complete`：公开数据匹配成功，所需展示字段已满足；AI 是否参与由字段来源解释。
- `partial`：可靠候选已写入，但部分可选字段仍缺失或 AI 不可用。
- `failed`：无可靠匹配、离线、超时、提供方失败或响应无效；只持久化安全错误码，不保存上游原始错误。
- 手动重刮失败时保留上一次成功数据，只更新尝试时间和非破坏性失败状态；不得清空已有简介、标签或封面。
- 网络恢复不自动弹出或重试；用户可从详情菜单重试。
- 页面卸载时取消不再需要的请求；过期请求返回后必须校验任务 token，不能覆盖较新的手动结果。

## 备份与兼容

- 备份导出保留 `enrichment` 及来源信息，使本地补全结果可迁移且离线可见。
- 备份验证器对新对象实行字段和长度校验，忽略未知字段，拒绝危险或畸形嵌套值。
- 旧版本备份缺少 `enrichment` 时正常导入为未补全状态。
- 恢复备份不会自动向网络批量发送所有书名或正文；用户之后可逐本手动补全。
- 远程封面仍作为现有 `bookCovers` 数据导出，不依赖远程 URL 才能显示。
- 不清库、不重写书籍 ID、不做阻塞式全库数据迁移。

## 无障碍

- 返回、更多、开始/继续阅读、目录和菜单项均至少 44×44px。
- 页面使用单一 `h1` 作为书名，区块标题保持层级连续。
- 封面装饰图使用空替代文本；若封面承载书名信息，也不重复朗读可见标题。
- 元数据状态使用 `aria-live="polite"`，自动完成不抢焦点、不使用打断式 alert。
- Popover 具备 `role="menu"` 与 `menuitem`，支持 Escape、外部点击和焦点归还。
- 返回后焦点回到原书籍主按钮，而不是更多按钮或页面顶部。
- 200% 文本缩放下不裁切主按钮、标题、作者和书目信息。
- 浅色、深色、护眼色与动态背景下保持现有语义颜色和可读对比度。

## 测试与验收

实施遵循 red-green-refactor，至少覆盖以下层次。

### 纯函数与数据层

1. EPUB OPF 标题、作者、ISBN 和语言提取，包括命名空间、缺失字段和畸形文件。
2. Open Library 与 Google Books 响应归一化。
3. 中英文标题、副标题、卷册、作者、ISBN 和语言的确定性评分。
4. 低置信候选拒绝、同分候选稳定选择。
5. 自动补全和手动重刮的字段级来源合并规则。
6. AI 只能写简介与标签，额外键和非法 JSON 被拒绝。
7. 描述、标签、标识符、片段和封面的长度/大小限制。
8. 更新补全信息不改变顶层本地信息、阅读数据或其他表。
9. 旧 IndexedDB 记录、旧备份与新备份往返兼容。

### API

1. Open Library 成功、无结果、超时、限流和畸形响应。
2. Google Books 有密钥时参与、无密钥时跳过且不报阻塞错误。
3. 一个提供方失败时仍采用另一个可靠结果。
4. 固定域名、重定向、响应体大小、图片 MIME 和 2 MB 封面限制。
5. 公开结果已包含简介与标签时绝不调用 AI。
6. AI 提供商协议、SSRF 防护、超时、非法输出和密钥不泄漏。
7. 请求长度限制与安全错误响应不包含上游敏感正文。

### 导航与组件

1. 列表、网格、精选书籍和搜索结果点击均进入详情，而不是直接进入阅读器。
2. 打开详情不调用 `getBook()`；点击阅读后只读取目标书籍。
3. 返回恢复来源页面、滚动位置、查询和焦点。
4. 搜索 → 详情 → 返回恢复搜索 Dock；详情中切换根标签清除 Push。
5. 开始/继续阅读文案跟随阅读位置，快速重复点击只有一次提交。
6. EPUB 查看目录复用阅读器目录；TXT 不显示无效目录操作。
7. 更多菜单焦点管理、单任务锁、成功/部分/失败状态。
8. 自动任务不阻塞导入，不弹 Toast，不改变当前焦点。
9. 删除当前详情书籍后安全退出。

### 视觉、动效与端到端

1. 390×844、窄屏和 200% 文本缩放。
2. 列表/网格两种共享封面来源，返回几何与焦点正确。
3. 浅色、深色、护眼、自定义背景、有封面和无封面。
4. 长标题、长作者、无简介、无标签、部分元数据和失败状态。
5. Reduced Motion 取消几何移动和按压缩放。
6. 模拟慢速公开 API、AI 未配置、离线、重复重刮与旧请求晚到。
7. 刮削前后断言阅读进度、目录、分组、书签、高亮、批注和工作区完全一致。

最终运行完整 Vitest、ESLint、Next.js 生产构建、`git diff --check` 和相关 Playwright 移动端流程。真实 iPhone Safari/PWA 仍作为共享封面转场、滚动恢复、动态背景和触控反馈的最终真机验收项。

## 非目标

- 不增加收藏、分享、书评、评分、推荐、书店或远程搜索页面。
- 不提供多个元数据候选的人工选择器或字段编辑器。
- 不让 AI 生成事实性书目字段。
- 不批量扫描或自动上传现有书库。
- 不引入服务器持久任务队列、Service Worker 后台同步或云端书库。
- 不预解析并持久化第二套目录数据。
- 不改变阅读器排版、阅读位置语义、批注或工作区架构。
- 不复制参考软件的视觉资产、品牌、配色或专有动效。

## 风险控制

- **错误匹配：** 安全阈值、ISBN 优先、标题冲突拒绝、字段级来源和非破坏性重刮共同限制污染。
- **第三方不稳定：** 单提供方隔离、短超时、部分成功、无密钥降级和手动重试保证阅读主链路独立。
- **隐私：** 公开查询不带正文；仅在 AI 补缺阶段读取单本书开篇，限制 6,000 字并沿用既有用户配置和披露。
- **封面安全：** 不接受任意代理 URL；固定提供方地址、MIME/大小/重定向限制后再持久化。
- **竞态：** 单书 single-flight、任务 token 和原子元数据写回阻止旧响应覆盖新结果。
- **性能：** 详情只读元数据；不全库读文件；局部更新不重放页面转场；背景继续复用单个现有模糊层。
- **兼容：** 可选嵌套对象、无新索引、旧备份默认未补全，避免破坏性迁移。

## 交付边界

本设计批准后先编写可执行实施计划，再在当前隔离 worktree 中按测试驱动方式实现。只有相关测试、完整测试、lint、生产构建和移动端验收通过后，才能提交功能代码并进入推送、部署与线上复核阶段；不得通过清库、重置或覆盖现有改动来解决兼容问题。
