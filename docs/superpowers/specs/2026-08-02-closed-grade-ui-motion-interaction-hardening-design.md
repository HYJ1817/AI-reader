# AI Reader UI 动效与交互闭源级硬化设计规格

**日期：** 2026-08-02  
**状态：** 待评审  
**范围：** 按压反馈、文字对比度、触控面积、背景调节性能、内容型弹层、文字缩放、主题一致性、手势策略和物理 iPhone 验收  
**关联规格：** `2026-08-02-closed-grade-detail-polish-design.md`、`2026-07-28-pwa-interaction-fluidity-design.md`

## 背景

AI Reader 已具备集中式动效 Token、根导航与推入页面、可中断底部弹层、阅读器手势仲裁、焦点陷阱、背景 `inert`、系统与应用内 reduced motion，以及覆盖主要导航路径的移动端自动化。现阶段不需要重新设计产品，也不需要更换动效框架。

本轮审计得到以下基线：

- Vitest 132 个测试文件、1217 个测试全部通过。
- ESLint 通过。
- iPhone 15 Pro Max Chromium 关键交互用例 56/57 通过。
- “图书操作表进入阅读空间”的按压反馈用例连续两次失败，按下 500ms 内没有检测到视觉状态变化。
- 浅色、深色和护眼色主题中的部分辅助文字与占位符低于普通文字 4.5:1 对比度要求。
- 多处高频触控目标为 32 至 42px，低于项目既定的 44px 一手操作基线。
- 自定义背景滑杆在拖动时同时更新预览和全屏背景的 `filter: blur()`。
- 自动化仅运行 Chromium，不能证明 Safari、主屏 PWA、VoiceOver 或 ProMotion 真机表现。

本规格承接已完成的细节优化，不重复设计书库空状态、Provider 保存说明或图标体系。目标是在不增加产品能力的前提下，将剩余问题收敛为明确、可验证的交互契约。

## 设计决策

### 采用方案：增量硬化

保留现有组件边界和视觉语言，针对审计证据逐项修复。每项修改必须有独立测试或真机验收标准，不借机重排页面或重写导航。

### 未采用方案

#### 整体重做动效与视觉系统

现有 `motionSystem`、`NavigationStack` 和 `MotionSheet` 已覆盖绝大多数路径。整体重做会扩大回归面，无法解释为什么需要替换已经通过验证的部分。

#### 只修改测试阈值或删除失败用例

失败用例已经独立复现，且探针检测的正是预期反馈属性。放宽 80ms 目标、延长 500ms 等待或移除操作表样本不能改善真实触感，因此不接受。

#### 只做视觉调整，不补真机验收

Chromium 模拟不能覆盖 WebKit 合成、软键盘、VoiceOver、主屏生命周期和 120Hz 节奏。闭源级完成声明必须包含实体设备证据。

## 目标

1. 所有日常操作在按下后的首个可绘制帧给出反馈，并在自动化中不超过 80ms。
2. 所有有意义的普通文字和占位符在实际表面上达到至少 4.5:1 对比度。
3. 所有高频按钮、标签页和输入目标的实际点击盒至少为 `44 × 44px`。
4. 拖动背景强度滑杆时不连续重算全屏模糊，不让视觉效果追赶手指。
5. 内容型全高弹层提供稳定、不透出底层文字的阅读表面。
6. 200% 文本、小屏、低高度、横屏和键盘视口下保留完整操作路径。
7. 阅读设置的主题变体有明确 Token，不依赖散落的硬编码颜色。
8. 底部弹层只保留一套权威关闭阈值和一套对应测试。
9. 物理 iPhone Safari、主屏 PWA 和 VoiceOver 验收完成后，才可以声明本轮闭源级体验完成。

## 非目标

- 不改变根导航、Push、Reader、Sheet 四层导航模型。
- 不更换 `motion/react`，不引入新的手势或动画依赖。
- 不调整书籍、分组、阅读进度、Provider 或备份数据结构。
- 不新增功能、引导页、成就动画、装饰性动效或连续背景动画。
- 不重新设计 EPUB/TXT 翻页、文本选择、高亮或问 AI 流程。
- 不追求逐帧复制 iOS 私有动画，也不复制 OpenMinis 源码或资源。
- 不通过提高测试阈值掩盖真实失败。

## 设计原则

### 反馈先于转场

用户按下控件后必须立即看到状态变化。导航仍由正常点击触发，不为了展示动画故意延迟业务动作。

### 语义文字必须可读

“低权重”不等于“低对比”。只要文字承载输入提示、状态、隐私说明或下一步，就必须满足普通文字对比度要求。低对比色只用于无语义装饰和合法的禁用状态。

### 视觉尺寸可以紧凑，点击盒不能紧凑

图标和文字可以保持当前密度，但实际交互区域必须达到 44px。相邻目标不能通过互相重叠的透明伪元素扩大。

### 拖动路径只做低成本工作

滑杆拖动期间允许更新数值、透明度和小范围预览，不允许连续更新全屏 `filter`、布局或持久化数据。

### 内容表面优先于材质效果

短操作表可以保留轻微半透明材质。全高阅读、输入和长内容表面应使用不透明背景，避免底层文字形成重影。

### 自动化证明架构，真机证明体验

Chromium 用于确定性回归和性能预算。Safari 真机用于最终判断触感、合成、键盘、VoiceOver 和主屏生命周期，两者不能互相替代。

## 详细设计

### 1. 确定性按压反馈

#### 统一状态契约

所有可操作组件应具备与自身类型相符的状态：

- `default`
- `hover`，仅在支持悬停的设备上生效
- `focus-visible`
- `pressed`
- `disabled`
- `loading`，仅异步控件需要

`pressed` 必须在 `pointerdown` 后的下一个可绘制帧出现。触点释放、取消、丢失 pointer capture、窗口失焦或组件卸载时必须清理。快速点击、长按和滑出控件后返回都不得留下粘滞状态。

#### 图书操作表

`ActionRow` 不再只依赖移动浏览器中的 `:active`。组件使用确定性的按压状态表达当前触点所有权，样式仍沿用现有视觉语言：

- 行背景使用轻量 tint，不引入阴影。
- 行本身不缩小，避免整组分隔线产生抖动。
- 图标容器可以使用不超过 `0.96` 的短促缩放，或使用 1px 位移，二者只选一种。
- Pointer 按压不设置 `aria-pressed`，因为该行不是可切换按钮。
- 键盘 Space 按下时显示 pressed，释放时触发；Enter 继续使用原生按钮行为。
- reduced motion 下保留即时颜色变化，移除位移和缩放。

导航不能等待一个固定时长再执行。内部 Sheet 转场自然保留 outgoing page 的可见帧，按压状态随旧页面退出清理。

#### 反馈时延标准

- 自动化记录 `pointerdown` 到背景、透明度或变换首次变化的时间。
- 每个交互家族至少保留一个样本：根标签、书籍行、阅读器控制、操作表行、工作区标签。
- 每个样本必须 `≤80ms`，探针等待上限继续保持 500ms。
- 若控件故意只使用颜色反馈，测试必须观察实际变化的元素，不通过观察无样式变化的子节点制造假失败。

### 2. 文字与占位符对比度

#### Token 分工

现有 `--text-tertiary` 同时服务于有意义文字、装饰图标和禁用状态，职责过多。本轮拆分为以下语义角色：

- `--text-primary`：标题、正文和主要标签。
- `--text-secondary`：可读辅助信息。
- `--text-tertiary`：仍然有意义的低权重文字，必须达到 4.5:1。
- `--text-placeholder`：输入占位符，必须达到 4.5:1，不再叠加降低对比度的 opacity。
- `--icon-tertiary`：Chevron、Grabber 等无文字语义装饰，可以低于普通文字标准。
- `--text-disabled`：仅用于真实禁用状态，不承载用户完成任务所需的信息。

每套主题分别定义这些角色，不用一组透明度覆盖所有背景。颜色必须在以下组合上验证：

- App 背景
- Primary surface
- Sheet surface
- Control fill
- Light、dark、sepia

Provider 提示、输入占位符、资料时间、空状态隐私说明和工作区层级标签优先迁移。图标、Grabber 和禁用按钮不应因文本修复而变得过重。

#### 高对比和降透明

在支持的环境中提供 `prefers-contrast: more` 增强规则，至少提高分隔线、辅助文字和焦点环对比度。该规则是渐进增强，基础主题本身仍必须达标。

若实体 iPhone 的“降低透明度”无法可靠映射到媒体查询，应把内容型弹层的不透明设计作为默认保障，不依赖该系统设置才能可读。

### 3. 44px 触控基线

以下目标纳入本轮：

- 阅读工作区标签页，当前约 36px。
- 消息复制、保存等操作，当前约 32px。
- 消息失败重试，当前约 32px。
- 资料行操作，当前约 36px。
- 阅读设置 Popover 行，当前约 40px。
- 自定义背景返回按钮，当前约 42px。
- 书库搜索框，当前约 42px。
- 藏书重命名输入框，当前约 34px。
- 手动模型输入框，当前约 38px。

实施约束：

- 优先使用 `min-height`、真实 padding 或包裹控件增大点击盒。
- 文本输入框本身达到 44px，不能只让不可点击的父行达到 44px。
- 相邻文字动作之间至少保留 8px 可见间距。
- 不使用会与相邻目标重叠的绝对定位伪元素。
- 允许控件在 200% 文本下自然增高，不设置会截断文字的固定高度。
- 调整共享选择器前检查所有调用点，避免无关页面产生密度回归。

### 4. 自定义背景滑杆性能

#### 状态分离

`CustomBackgroundSettingsSurface` 增加本地预览值。滑杆拖动时：

1. 即时更新百分比文案。
2. 只在受控预览区域更新低成本属性，优先使用遮罩 opacity。
3. 不更新全屏 `AmbientBookBackground` 的 blur 和 inset。
4. 不连续写入持久化偏好。

在 `pointerup`、键盘单次调整、明确失焦或页面正常关闭时提交最新值。`pointercancel` 保留最后一个有效值并只提交一次。组件卸载前若存在未提交草稿，使用同一提交路径完成，不创建第二套保存逻辑。

#### 视觉保持

提交后可以通过短 opacity 交叉淡化切换最终模糊结果，但不能对 `filter` 本身做 280ms 连续过渡。预览与最终背景允许在拖动期间存在轻微精度差异，释放后必须在一个短状态变化内一致。

#### 性能标准

- 一次完整滑杆拖动的 PerformanceObserver Long Task 数量为 0。
- 拖动期间帧间隔 p95 不超过 20ms，最大值不超过 34ms。
- 拖动过程 CLS 为 0。
- 全屏背景的 blur/inset 更新次数为每次提交至多一次，而不是每个 `input` 事件一次。
- reduced motion 不改变数据提交语义，只取消可见交叉淡化。

### 5. 内容型全高弹层

Sheet 按用途区分两种材质：

#### 短操作型

书籍操作、确认、分组等短弹层继续使用现有高不透明材质和 Backdrop。其内容短，底层上下文的轻微存在感有助于表达层级。

#### 内容型

阅读空间、Ask AI 长会话、资料详情和长表单使用不透明 surface。空白区域不能看到底层书名、列表或按钮轮廓。

实现上通过 Sheet 级语义变体或 CSS 变量选择填充，不修改 `MotionSheet` 的拖动、焦点、历史和关闭协议。不要通过增加更重的 `backdrop-filter` 解决重影，以免把可读性问题转化为合成成本。

### 6. 文字缩放与响应式覆盖

#### 字号策略

新增和本轮触达的语义文字使用现有类型 Token 或 `rem`，不再新增固定 px 字号。既有固定字号按任务路径逐步迁移，不进行一次性全文件机械替换。

必须优先覆盖：

- Provider 配置字段、提示和 sticky action。
- 阅读空间标题、标签、状态、消息操作和 Composer。
- 图书操作表标签。
- 自定义背景设置。
- 阅读设置 Popover。

图标、Hairline、Grabber 和非文字几何可以继续使用 px。

#### 验证矩阵

自动化至少覆盖以下视口类别：

| 类别 | 代表尺寸 | 重点 |
|---|---:|---|
| 紧凑竖屏 | 320×568、375×667 | 标题折行、Sticky action、触控拥挤 |
| 常规竖屏 | 390×844 | 日常路径 |
| 大屏竖屏 | 430×932 | 当前主要性能基线 |
| 横屏 | 667×375 或相近尺寸 | Sheet 高度、键盘、固定控制 |
| 键盘视口 | 可视高度减少约 320px | 输入框、Composer、关闭按钮 |

200% 文本验证不能只断言一个书名字号。每条核心路径必须验证：无水平页面滚动、操作可见、焦点可见、按钮文字不裁切、关闭与保存入口可达。

### 7. 阅读设置主题一致性

当前阅读设置 Popover 和自定义设置 Sheet 使用独立的奶油色与深灰硬编码。保留其“阅读器控制层”身份，但改为明确的主题变体：

- `light`：高对比浅色控制表面。
- `sepia`：与阅读护眼背景同色相的控制表面。
- `dark`：保留深色控制表面。
- `system`：跟随实际解析后的主题，不在组件内部重复媒体查询。

颜色通过 `--reader-control-*` Token 表达，覆盖 surface、elevated surface、primary text、secondary text、separator、pressed fill 和 focus ring。主题切换只做短 crossfade 或立即更新，不做整页空间动画。

如果视觉评审决定阅读设置始终使用深色，也必须通过显式 `dark-control` 变体实现，并在浅色和护眼阅读背景上验证边界与对比度，不能继续依赖散落的十六进制值。

### 8. 单一手势策略来源

`MotionSheet` 当前使用 `navigationGestures.shouldCompleteSheetDismiss`。`motionInteractions.shouldDismissSheet` 存在不同的中速关闭分支，但没有被产品代码调用。

本轮以正在运行的 `navigationGestures` 策略为权威：

- 距离阈值：`min(140px, sheetHeight × 0.28)`。
- 快速下甩：速度至少 900px/s，且位移至少 24px。
- 不保留另一套 480px/s、18% 距离的未使用策略。

删除失效 helper 前，先把需要保留的边界测试迁移到权威模块。文档、单元测试和 `MotionSheet` 必须引用同一函数。若真机验证表明阈值需要调整，只修改一个来源，并同时更新测试与验收记录。

### 9. 物理 iPhone 发布验收

#### 最低设备范围

- 一台支持当前目标 iOS 的常规 iPhone。
- 一台 120Hz ProMotion iPhone，优先 iPhone 15 Pro Max 或同级设备。
- Safari 浏览器和添加到主屏后的 standalone PWA 各运行一轮。

#### 必测路径

1. 根标签连续切换和快速反向切换。
2. 图书列表按压、操作表按压、进入阅读空间。
3. Push 页面边缘返回、取消和重新武装。
4. Sheet 打开、拖动、取消、快速甩动和嵌套返回。
5. EPUB/TXT 翻页、滚动、文本选择和控制条显示隐藏。
6. 输入框聚焦、中文输入法候选栏、上一项/下一项工具条和键盘收起。
7. 自定义背景滑杆连续拖动。
8. 200% 页面缩放或 Safari 文本大小调整。
9. VoiceOver 顺序、弹层隔离、焦点恢复和禁用状态说明。
10. 前后台切换、锁屏恢复、Standalone 重开和版本更新后首次启动。

#### 证据

- 记录 iOS、Safari、设备型号、是否 Standalone、低电量模式和测试版本 SHA。
- 关键转场保留屏幕录制，ProMotion 设备保留性能时间线或 Safari Web Inspector 证据。
- 记录失败步骤、期望、实际、复现次数和是否只在 Safari/PWA 出现。
- 物理设备未通过前，不使用“120fps 已完成”“Safari 已验收”或“闭源级体验完成”的表述。

## 组件与代码边界

- `ActionRow` 或等价共享按压层负责确定性 pressed 状态，业务动作仍由调用方提供。
- `motionSystem.ts` 继续作为时长、缓动和 reduced-motion 角色来源，不在组件新增重复数字。
- `navigationGestures.ts` 作为 Sheet 和边缘导航手势阈值来源。
- `MotionSheet` 只消费权威手势策略，不拥有第二套数学判断。
- `CustomBackgroundSettingsSurface` 负责本地预览草稿和一次性提交。
- `AmbientBookBackground` 只接收已提交的偏好，不感知滑杆手势生命周期。
- `globals.css` 负责跨主题语义颜色 Token。
- `page.module.css` 负责组件密度、pressed 表达和 Sheet 材质变体。
- 不在 `page.tsx` 增加与视觉反馈有关的业务状态。

## 状态与错误恢复

- Pointer 取消或丢失 capture 后，控件恢复 default，不触发动作。
- 按压后路由目标失效时，保留现有导航恢复逻辑，不让 pressed 状态阻塞退出。
- 背景滑杆提交失败时保留当前草稿值，显示既有设置错误通道，不回退成未定义值。
- 主题 Token 缺失时回退到现有 `surface-primary` 与 `text-primary`，不能出现透明文字。
- 物理键盘、中文输入法或 visualViewport 缺失时，保持现有滚动可达性，不猜测固定键盘高度。

## 实施分批

### 批次 A：发布前正确性

1. 操作表确定性按压反馈及 80ms 回归测试。
2. 文字与占位符语义 Token、三主题对比度测试。
3. 本轮列出的 44px 触控目标和实际几何测试。

### 批次 B：性能与内容稳定性

1. 背景滑杆本地预览与提交分离。
2. 移除拖动期间的全屏 filter 更新和 filter transition。
3. 阅读空间等内容型 Sheet 改为不透明表面。

### 批次 C：适配与系统收口

1. 核心路径相对字号迁移和扩展视口矩阵。
2. 阅读设置主题 Token 化。
3. 合并 Sheet 关闭策略，删除失效 helper。

### 批次 D：真机验收

完成 Safari、Standalone PWA、VoiceOver 和 ProMotion 证据。批次 D 可以发现并修复平台差异，但不得重新打开无证据的全局视觉改造。

每个批次独立提交并通过自己的测试。批次 A 至 C 完成后运行完整本地门槛，批次 D 通过后才更新完成声明和部署记录。

## 验证策略

### Vitest

- Pressed 状态进入、释放、取消、丢失 capture 和卸载清理。
- 三主题文字、占位符和实际背景组合的对比度函数测试。
- Sheet 关闭距离、速度、边界值和单一来源契约。
- 背景滑杆拖动只更新本地预览，提交只调用一次偏好更新。
- 内容型和操作型 Sheet 材质变体契约。
- 阅读设置主题 Token 完整性。

### Playwright

- 保留并修复现有 `press feedback appears within 80 ms` 用例，不改变阈值。
- 对所有本轮触控目标读取实际 Bounding Box，宽高不小于 44px。
- Light、dark、sepia 下采样实际计算样式并验证文字对比度。
- 自定义背景滑杆拖动期间记录 Long Task、帧节奏和全屏背景样式更新次数。
- 内容型 Sheet 的计算背景色 alpha 为 1，并用截图验证底层高对比文字不透出。
- 320、375、390、430px 竖屏和代表性横屏完成核心路径。
- 200% 文本下覆盖 Provider、操作表、阅读空间、背景设置和阅读设置。
- Reduced motion 下所有路径功能相同，pressed 仍有非空间反馈。

## 成功标准

满足以下条件后，代码部分可以进入真机验收：

- 关键交互按压反馈全部 `≤80ms`，操作表失败用例稳定通过。
- 有意义文字和占位符在 Light、dark、sepia 实际背景上达到至少 4.5:1。
- 本轮列出的实际触控目标全部至少 `44 × 44px`。
- 背景滑杆拖动不连续更新全屏 filter，PerformanceObserver Long Task 数量为 0。
- 内容型全高 Sheet 不透出底层文字或按钮轮廓。
- 200% 文本、小屏、横屏和键盘视口下不存在阻塞操作的裁切或水平页面滚动。
- 阅读设置颜色由明确主题 Token 提供，主题切换没有闪白或不可读状态。
- Sheet 关闭阈值只有一个产品代码来源，测试与实现一致。
- 全量测试、Lint、Build、两个 Playwright 项目和 `git diff --check` 通过。

满足以下条件后，才可以声明本轮闭源级体验完成：

- Safari 和 Standalone PWA 真机路径通过。
- VoiceOver 能正确隔离 Sheet、朗读状态并恢复焦点。
- ProMotion 设备不存在可感知的重复掉帧、触点滞后或动画尾帧卡顿。
- 验收记录包含设备、系统、版本 SHA、证据和已知限制。

## 风险与回退

- 提高辅助文字对比度可能让界面变重。通过拆分文本和装饰图标 Token 控制，而不是整体加深所有灰色。
- 扩大目标可能改变密度。优先增加真实垂直 padding，并逐表面截图比较，不使用全局按钮高度覆盖。
- 不透明内容 Sheet 可能削弱层级感。Backdrop、圆角和进入转场继续表达层级，不用内容透出来表达。
- 滑杆预览与最终背景可能短暂不同。释放后的短 opacity 交叉淡化负责对齐，不恢复 filter 动画。
- 真机发现 WebKit 专属问题时，仅针对有证据的路径修复；若无法安全修复，回退该批次并保留验收阻塞状态。
